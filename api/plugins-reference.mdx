kkRPC's plugin system lets you intercept every stage of receive-side request handling: before the method runs (`onRequest`), around the handler call (`wrapHandler`), after a successful result (`onResponse`), and after a failure (`onError`). Each request carries a shared mutable `state` bag that passes context across all hooks in the same pipeline. This page documents the plugin interface, every context type, and all the built-in plugin and feature packages.

---

## `RPCPlugin` Interface

The `RPCPlugin` interface is the contract for any plugin passed to `expose()` or `RPCChannel`. All four hooks are optional — implement only the ones you need.

```typescript plugins.ts
import type { RPCPlugin } from "kkrpc"

interface RPCPlugin {
  /** Optional plugin name for diagnostics. */
  name?: string

  /** Inspect or mutate the incoming request before handler execution. */
  onRequest?(ctx: RPCRequestContext): void | Promise<void>

  /** Wrap local handler execution, optionally replacing or transforming the result. */
  wrapHandler?(
    ctx: RPCHandlerContext,
    next: () => Promise<unknown>
  ): Promise<unknown>

  /** Inspect or mutate a successful response before it is serialized. */
  onResponse?(ctx: RPCResponseContext): void | Promise<void>

  /** Observe or replace an error before it is serialized. */
  onError?(ctx: RPCErrorContext): void | Promise<void>
}
```

Plugins run in the order they appear in the `plugins` array. `onRequest`, `onResponse`, and `onError` are called sequentially. `wrapHandler` hooks are composed as an onion chain, so the first plugin wraps all subsequent ones.

## Context Types

### `RPCRequestContext`

Passed to `onRequest` and `wrapHandler` hooks. The `args` and `value` fields are mutable — assign to them to transform inputs before the handler sees them.

<ResponseField name="id" type="string">
  Compact request identifier generated by the channel.
</ResponseField>

<ResponseField name="operation" type="RPCOperation">
  The operation being handled: `"call"`, `"get"`, `"set"`, or `"new"`.
</ResponseField>

<ResponseField name="path" type="string[]">
  Property path on the exposed local API (e.g. `["users", "create"]`).
</ResponseField>

<ResponseField name="method" type="string">
  Dot-joined path, useful for logging and validator lookup (e.g. `"users.create"`).
</ResponseField>

<ResponseField name="args" type="unknown[]">
  Decoded request arguments. Mutate this array to transform inputs before handler invocation.
</ResponseField>

<ResponseField name="value" type="unknown">
  Decoded setter value, present only for `"set"` operations.
</ResponseField>

<ResponseField name="meta" type="RPCMessageMetadata | undefined">
  Protocol-level metadata attached to the incoming request by the caller.
</ResponseField>

<ResponseField name="state" type="Record<string, unknown>">
  Per-request scratch space shared across all plugin hooks for this request.
</ResponseField>

---

### `RPCHandlerContext`

Extends `RPCRequestContext` with one additional field, passed to `wrapHandler` only.

<ResponseField name="localAPI" type="object">
  The local API object currently exposed by this channel.
</ResponseField>

---

### `RPCResponseContext`

Passed to `onResponse` hooks after the handler returns successfully. The `result` field is mutable.

<ResponseField name="id" type="string">
  Request identifier matching the original request.
</ResponseField>

<ResponseField name="operation" type="RPCOperation">
  The operation that completed.
</ResponseField>

<ResponseField name="path" type="string[]">
  Property path on the exposed local API.
</ResponseField>

<ResponseField name="method" type="string">
  Dot-joined method path.
</ResponseField>

<ResponseField name="result" type="unknown">
  Mutable result value. Assign to this field to transform or replace what is sent back to the caller.
</ResponseField>

<ResponseField name="meta" type="RPCMessageMetadata | undefined">
  Protocol-level metadata from the original request.
</ResponseField>

<ResponseField name="state" type="Record<string, unknown>">
  Per-request state bag, same instance as in `RPCRequestContext`.
</ResponseField>

---

### `RPCErrorContext`

Passed to `onError` hooks after the handler or any earlier plugin throws. The `error` field is mutable.

<ResponseField name="id" type="string">
  Request identifier matching the original request.
</ResponseField>

<ResponseField name="operation" type="RPCOperation">
  The operation that failed.
</ResponseField>

<ResponseField name="path" type="string[]">
  Property path on the exposed local API.
</ResponseField>

<ResponseField name="method" type="string">
  Dot-joined method path.
</ResponseField>

<ResponseField name="error" type="unknown">
  Mutable error. Assign to this field to replace or enrich the error before it is serialized and sent.
</ResponseField>

<ResponseField name="meta" type="RPCMessageMetadata | undefined">
  Protocol-level metadata from the original request.
</ResponseField>

<ResponseField name="state" type="Record<string, unknown>">
  Per-request state bag, same instance as in `RPCRequestContext`.
</ResponseField>

## `kkrpc/validation`

The validation plugin integrates any [Standard Schema v1](https://standardschema.dev/) compatible library — Zod, Valibot, ArkType, and others — into the kkRPC request pipeline. Input validation runs before the handler; output validation runs after. Transformed values from the schema replace the original arguments or result.

### `validationPlugin(validators)`

```typescript validation.ts
import { validationPlugin } from "kkrpc/validation"
import type { ValidatorMap } from "kkrpc/validation"

// Type-first usage
function validationPlugin<API extends object>(
  validators: ValidatorMap<API> | undefined
): RPCPlugin

// Untyped / schema-first usage
function validationPlugin(
  validators: Record<string, unknown> | undefined
): RPCPlugin
```

The returned plugin has `name: "validation"` and registers `onRequest` (input) and `onResponse` (output) hooks.

**Type-first example:**

```typescript type-first.ts
import { expose } from "kkrpc"
import { validationPlugin, type ValidatorMap } from "kkrpc/validation"
import { z } from "zod"

interface MathAPI {
  add(a: number, b: number): Promise<number>
}

const validators: ValidatorMap<MathAPI> = {
  add: {
    input: z.tuple([z.number(), z.number()]),
    output: z.number(),
  },
}

expose(api, transport, { plugins: [validationPlugin<MathAPI>(validators)] })
```

---

### `ValidatorMap<API>`

A recursive type that mirrors the shape of your API. Method leaves hold `MethodValidators`; nested objects hold nested `ValidatorMap` values.

```typescript validator-map.ts
type ValidatorMap<API> = {
  [K in keyof API]?: API[K] extends (...args: infer A) => infer R
    ? MethodValidators<A, R>
    : API[K] extends Record<string, unknown>
    ? ValidatorMap<API[K]>
    : never
}

interface MethodValidators<Args extends unknown[] = unknown[], Return = unknown> {
  /** Schema for non-callback method arguments. */
  input?: StandardSchemaV1<FilterCallbacks<Args>, FilterCallbacks<Args>>
  /** Schema for the awaited method result. */
  output?: StandardSchemaV1<UnwrapPromise<Return>, UnwrapPromise<Return>>
}
```

Callback function arguments are automatically filtered out before input validation runs, so `input` schemas describe only serializable arguments.

---

### `StandardSchemaV1`

kkRPC's minimal Standard Schema interface. Any schema library that exposes the `~standard` property conforms to this interface.

<ResponseField name="~standard.version" type="1">
  Standard Schema major version number.
</ResponseField>

<ResponseField name="~standard.vendor" type="string">
  Schema library identifier (e.g. `"zod"`, `"valibot"`).
</ResponseField>

<ResponseField name="~standard.validate" type="(value: unknown) => Result<Output> | Promise<Result<Output>>">
  Validates a value and returns a success result with the (possibly transformed) value, or a failure result with issues.
</ResponseField>

<ResponseField name="~standard.types" type="Types<Input, Output> | undefined">
  Optional static type metadata used for TypeScript inference.
</ResponseField>

---

### `RPCValidationError`

Thrown by the validation plugin when input or output validation fails. Extends the standard `Error` class.

```typescript rpc-validation-error.ts
class RPCValidationError extends Error {
  readonly phase: "input" | "output"
  readonly method: string
  readonly issues: ReadonlyArray<StandardSchemaV1.Issue>

  constructor(
    phase: "input" | "output",
    method: string,
    issues: ReadonlyArray<StandardSchemaV1.Issue>
  ) {
    // Sets this.name = "RPCValidationError" and this.message inside constructor
  }
}

function isRPCValidationError(error: unknown): error is RPCValidationError
```

<ResponseField name="phase" type='"input" | "output"'>
  Whether input or output validation triggered the error.
</ResponseField>

<ResponseField name="method" type="string">
  Dot-joined method path that failed validation (e.g. `"users.create"`).
</ResponseField>

<ResponseField name="issues" type="ReadonlyArray<StandardSchemaV1.Issue>">
  Validation issues reported by the schema library. Each issue has a `message` string and an optional `path`.
</ResponseField>

`isRPCValidationError(error)` is a type-guard helper that returns `true` when `error` is an `RPCValidationError` instance, narrowing the type for safe field access.

### Schema-first Helpers: `defineMethod`, `defineAPI`, `extractValidators`

The schema-first approach embeds validators directly in the API implementation object. `defineMethod` attaches schemas to a handler function as a hidden property. `defineAPI` is a passthrough that preserves the shape for TypeScript inference. `extractValidators` walks the API object and recovers the hidden validator map.

```typescript schema-first.ts
import {
  defineAPI,
  defineMethod,
  extractValidators,
  validationPlugin,
  type InferAPI,
} from "kkrpc/validation"
import { expose, wrap } from "kkrpc"
import { z } from "zod"

const api = defineAPI({
  add: defineMethod(
    { input: z.tuple([z.number(), z.number()]), output: z.number() },
    async (a, b) => a + b
  ),
})

// Server side
expose(api, transport, {
  plugins: [validationPlugin(extractValidators(api))],
})

// Client side — InferAPI derives the callable remote type
const remote = wrap<InferAPI<typeof api>>(clientTransport)
```

```typescript schema-first-signatures.ts
function defineMethod<
  InputSchema extends StandardSchemaV1,
  OutputSchema extends StandardSchemaV1
>(
  schemas: MethodSchemaConfig<InputSchema, OutputSchema>,
  handler: (
    ...args: StandardSchemaV1.InferOutput<InputSchema> extends readonly unknown[]
      ? StandardSchemaV1.InferOutput<InputSchema>
      : [StandardSchemaV1.InferOutput<InputSchema>]
  ) => Promise<StandardSchemaV1.InferOutput<OutputSchema>>
): DefinedMethod<InputSchema, OutputSchema>

function defineAPI<T extends Record<string, unknown>>(api: T): T

function extractValidators<T extends Record<string, unknown>>(
  api: T
): Record<string, unknown>
```

## `kkrpc/middleware`

The middleware plugin wraps local handler execution in an onion chain, similar to Express or Koa middleware. It provides a simple way to add logging, authorization, metrics, or argument transformation without modifying the exposed API.

### `middlewarePlugin(interceptors)`

```typescript middleware.ts
import { middlewarePlugin } from "kkrpc/middleware"
import type { MiddlewareHandler, RPCCallContext } from "kkrpc/middleware"

function middlewarePlugin(
  interceptors: readonly MiddlewareHandler[]
): RPCPlugin
```

The returned plugin has `name: "middleware"` and registers a `wrapHandler` hook that runs all interceptors in onion order.

---

### `MiddlewareHandler`

```typescript middleware-handler.ts
type MiddlewareHandler = (
  ctx: RPCCallContext,
  next: () => Promise<unknown>
) => Promise<unknown>
```

Code before `await next()` runs on the way in; code after runs on the way out. Return without calling `next()` to short-circuit handler execution. Calling `next()` more than once throws an error.

---

### `RPCCallContext`

The context object passed to every middleware function. `args` and `state` are mutable.

<ResponseField name="id" type="string">
  Compact RPC request identifier.
</ResponseField>

<ResponseField name="method" type="string">
  Dot-joined method path being handled (e.g. `"auth.login"`).
</ResponseField>

<ResponseField name="args" type="unknown[]">
  Mutable handler arguments. Replace this array before calling `next()` to transform inputs.
</ResponseField>

<ResponseField name="meta" type="RPCMessageMetadata | undefined">
  Optional request metadata sent by the caller.
</ResponseField>

<ResponseField name="state" type="Record<string, unknown>">
  Per-call shared state for cross-cutting concerns: auth tokens, logging spans, metrics references, etc.
</ResponseField>

**Logging middleware example:**

```typescript logging-middleware.ts
import { expose } from "kkrpc"
import { middlewarePlugin, type MiddlewareHandler } from "kkrpc/middleware"

const logger: MiddlewareHandler = async (ctx, next) => {
  const start = Date.now()
  try {
    const result = await next()
    console.log(`[RPC] ${ctx.method} OK (${Date.now() - start}ms)`)
    return result
  } catch (error) {
    console.error(`[RPC] ${ctx.method} ERR (${Date.now() - start}ms)`, error)
    throw error
  }
}

expose(api, transport, { plugins: [middlewarePlugin([logger])] })
```

## `kkrpc/superjson`

The SuperJSON codec preserves rich JavaScript values — `Date`, `Map`, `Set`, `BigInt`, `undefined`, typed arrays — when a transport uses string wire values. Compose it with `createTransport` when the underlying platform reads and writes strings.

### `superJsonCodec()`

```typescript superjson.ts
import { superJsonCodec, superJsonLineCodec } from "kkrpc/superjson"
import { createTransport } from "kkrpc/transport"

function superJsonCodec<TMessage>(): Codec<TMessage, string>
function superJsonLineCodec<TMessage>(): Codec<TMessage, string>

// Lowercase aliases are also exported:
// superjsonCodec, superjsonLineCodec
```

`superJsonCodec` encodes with `superjson.stringify()` and decodes with `superjson.parse()`. `superJsonLineCodec` appends a newline to each encoded frame and trims before decoding — use this with `stdioPlatform` or any line-framed platform.

**Capabilities:** `{ transfer: false }` — SuperJSON serializes to strings and cannot preserve transferable ownership.

**Example:**

```typescript superjson-example.ts
import { createTransport } from "kkrpc/transport"
import { stdioPlatform } from "kkrpc/stdio"
import { superJsonLineCodec } from "kkrpc/superjson"

const transport = createTransport({
  platform: stdioPlatform({ readable, writable }),
  codec: superJsonLineCodec(),
})
```

<Note>
`superJsonCodec` requires `superjson` as a peer dependency. It is not included in the main `kkrpc` bundle.
</Note>

## `kkrpc/inspector`

The inspector observes RPC plugin hooks and writes normalized `InspectEvent` records to one or more backends. Use `MemoryBackend` in tests, `consoleBackend()` for local debugging, or provide a custom `InspectorBackend` for telemetry pipelines.

### `createInspector(config?)`

```typescript inspector.ts
import { createInspector } from "kkrpc/inspector"
import type { InspectorConfig, InspectorOptions } from "kkrpc/inspector"

function createInspector(config?: InspectorConfig): KKRPCInspector
```

<ResponseField name="config.backends" type="InspectorBackend[]">
  Backends that receive sanitized inspector events.
</ResponseField>

<ResponseField name="config.options" type="InspectorOptions">
  Filtering, sanitization, and latency tracking options.
</ResponseField>

<ResponseField name="config.options.filter" type="(event: InspectEvent) => boolean">
  Drop events for which the predicate returns `false`.
</ResponseField>

<ResponseField name="config.options.sanitize" type="(event: InspectEvent) => InspectEvent">
  Transform or redact events before they are recorded (e.g. strip sensitive argument values).
</ResponseField>

<ResponseField name="config.options.trackLatency" type="boolean">
  Track request/response timings by request id. When enabled, `InspectorStats.avgLatency` is populated and response events carry a `duration` field.
</ResponseField>

---

### `KKRPCInspector`

The class returned by `createInspector`. Implements `InspectorBackend` and acts as both the event router and the plugin factory.

```typescript kkrpc-inspector.ts
class KKRPCInspector {
  /** Create an RPCPlugin bound to this inspector. */
  plugin(sessionId?: string): RPCPlugin

  /** Add a backend to future events. */
  addBackend(backend: InspectorBackend): void

  /** Remove a backend and call its optional destroy() hook. */
  removeBackend(backend: InspectorBackend): void

  /** Return a defensive copy of current aggregate statistics. */
  getStats(): InspectorStats

  /** Flush all backends that expose a flush() hook. */
  flush(): Promise<void>

  /** Destroy all backends and clear latency tracking state. */
  destroy(): void

  /** Log one event directly through this inspector. */
  log(event: InspectEvent): void
}
```

**Usage:**

```typescript inspector-usage.ts
import { expose } from "kkrpc"
import {
  createInspector,
  MemoryBackend,
  consoleBackend,
} from "kkrpc/inspector"

const memory = new MemoryBackend()
const inspector = createInspector({
  backends: [memory, consoleBackend(true)],
  options: { trackLatency: true },
})

expose(api, transport, {
  plugins: [inspector.plugin("server-session-1")],
})

// Later — inspect recorded events
const stats = inspector.getStats()
console.log("avg latency:", stats.avgLatency)
```

<ResponseField name="sent" type="number">

<ResponseField name="received" type="number">

### `MemoryBackend`

An in-memory backend that stores events in insertion order. Useful in tests and local assertions.

```typescript memory-backend.ts

class MemoryBackend implements InspectorBackend {
  events: InspectEvent[]

  log(event: InspectEvent): void
  query(query?: MemoryBackendQuery): InspectEvent[]

}
```

<ParamField body="query.sessionId" type="string">
  Filter events to a specific session id.
</ParamField>

<ParamField body="query.direction" type='"sent" | "received"'>
  Filter events by direction.
</ParamField>

### `consoleBackend(pretty?)`

Creates a backend that writes JSON-serialized inspector events to `console.log`.

```typescript console-backend.ts
import { consoleBackend } from "kkrpc/inspector"

function consoleBackend(pretty?: boolean): InspectorBackend
```

When `pretty` is `true`, events are formatted with `JSON.stringify(event, null, 2)`.

## `kkrpc/relay`

The relay bridges two transports without exposing a local API, forwarding raw `RPCMessage` objects in both directions. This is useful for proxy processes, test harnesses, and any scenario where an intermediate node needs to pass traffic through without participating in the RPC exchange.

### `relayTransport(left, right, options?)`

```typescript relay.ts
import { relayTransport } from "kkrpc/relay"
import type { RelayController, RelayTransportOptions } from "kkrpc/relay"

function relayTransport(
  left: Transport<RPCMessage>,
  right: Transport<RPCMessage>,
  options?: RelayTransportOptions
): RelayController
```

<ParamField body="options.onClose" type="(side: 'left' | 'right', reason?: Error) => void">
  Called once after the relay auto-disposes because one side's `onClose` fired. Only invoked when the closing transport implements `onClose`.
</ParamField>

<ParamField body="options.closeOtherSide" type="boolean">
  When `true`, also closes the surviving transport when one side closes. Defaults to `false`.
</ParamField>

---

### `RelayController`

<ResponseField name="dispose" type="() => void">
  Stops forwarding messages in both directions by unsubscribing from both transports. Does not close either transport unless `closeOtherSide` was set.
</ResponseField>

**Example:**

```typescript relay-example.ts
import { relayTransport } from "kkrpc/relay"

const relay = relayTransport(transportA, transportB, {
  closeOtherSide: true,
  onClose(side, reason) {
    console.log(`relay: ${side} side closed`, reason)
  },
})

// Later — stop forwarding
relay.dispose()
```

When the destination transport reports `capabilities.transfer === true`, the relay automatically collects transferable objects from the message payload and forwards them with the `send()` call.

<Note>
When a transport implements `onClose`, the relay auto-disposes once either side closes — because a closed side can no longer forward messages. Transports without `onClose` do not trigger auto-dispose, so `relay.dispose()` must be called manually on teardown.
</Note>
